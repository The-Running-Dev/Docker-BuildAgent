# 2.0.0 Release Notes

Canonical contract (PowerShell module): [PSModule.requirements.md](https://github.com/The-Running-Dev/Docker-BuildAgent/blob/main/PSModule.requirements.md)

## 💥 Breaking Changes

- **The PowerShell module's default image is pinned to the module's own version.** With no
  image configured, `Docker-BuildAgent` 2.0.0 runs `ghcr.io/the-running-dev/build-agent:2.0.0`
  instead of `ghcr.io/the-running-dev/build-agent:latest`, so a module and the image it drives
  always match. To keep the previous behaviour, pass the reference explicitly:
  `Set-BuildAgentConfig -DockerImage ghcr.io/the-running-dev/build-agent:latest ...`. An
  override is always used verbatim. See the [migration guide](../migration.md).
- **Launcher failures carry a stable code and exit status.** `Invoke-Build` and
  `Set-BuildAgentConfig` raise terminating errors whose `FullyQualifiedErrorId` is the code
  and whose `Exception.Data['ExitCode']` is the status: `WorkspaceInvalid` (3),
  `DockerUnavailable` (5), `ImageUnavailable` (5), and `BuildFailed` (the container's own
  status, unchanged). A configured image that cannot be obtained now fails; it is never
  replaced by another version. See the [migration guide](../migration.md).
- **Map-derived environment no longer overwrites a variable that is already set.** Values
  generated from `.build.env.map` used to replace a variable already present in the process
  environment; from 2.0.0 the variable you set wins and the generated value applies only where
  nothing is set. See the [migration guide](../migration.md).

## 🗑️ Deprecations

None.
